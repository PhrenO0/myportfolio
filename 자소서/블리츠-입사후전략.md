# 블리츠 입사 후 전략 — "카테고리 1등 브랜드 만들기" 플레이북

> 직무의 실체(상세 JD 기준): **브랜드 메이커.** 배달 시장 100개 카테고리 중 하나를 맡아, 빈 영역을 찾아 **컨셉·네이밍·메뉴·가격·비주얼까지 브랜드 하나를 직접 설계·런칭하고, 초기 반응 데이터로 고쳐 카테고리 1등으로 만든다.** 운영은 Agent(공고상 AKOS)가 대신하므로 나는 '무엇을 만들지·어디에 베팅할지'에 집중.
> 이 문서 = 내가 제안하는 "우리만의 공식"의 초안. 목표: **관찰-가설-적용-검증 사이클로 맡은 카테고리 1등.**

---

## 0. North Star & 성공 지표
- **North Star:** 맡은 카테고리에서 **우리 브랜드를 1등**으로.
- **1등의 정의(선행지표 → 후행지표):** 카테고리 내 노출·주문 순위 상승을 **후행지표**로 두되, 매일 관리하는 **선행지표**는 ① 할인 제외 **재구매율(14/30일)** ② **객단가·공헌이익** ③ 상세 **전환율(CVR)** ④ 리뷰의 **긍정 키워드 비중**. → "많이 팔리는 브랜드"가 아니라 **"할인 없이도 다시 시키는, 남는 브랜드"**가 1등의 본질.

## 1. [관찰] 카테고리 진단 — 지도부터 그린다
- 맡은 카테고리(예: 국밥/찜닭/곱도리탕) 상위 브랜드를 전수 스캔: 가격대·메뉴 구성·대표 이미지·리뷰 키워드·인기 라벨·배달비 노출.
- **경쟁이 '어떻게 이기고 있는지'를 분해** → 강점 패턴(왜 팔리나)과 공백(아무도 안 채운 것)을 지도화.
- **내 무기:** 리뷰 수천 개를 **LLM으로 태깅·클러스터링**해 불만·요청을 구조화(질적연구식 심층 + AI 속도). 남들이 눈으로 읽을 때 나는 데이터로 규명.

## 2. [가설] 빈 영역 = 진짜 기회인가, 지뢰인가 (Framework A)
빈자리를 찾으면 **베팅 전에 3관문**을 통과시킨다:
1. **수요 신호 있나?** 급상승 키워드·검색량, 리뷰의 "이런 거 없나요" 요청, 인접 카테고리 불만. (신호 없으면 그냥 니치)
2. **공급이 없는 '이유'가 치명적인가?** 원가율 안 나옴 / 조리 난이도·재현성 낮음 / 배달 부적합(눅눅·온도·국물 넘침) / 객단가가 너무 낮아 배달비를 못 버팀. (이유가 구조적이면 지뢰)
3. **그 이유를 '블리츠라서' 우회할 수 있나?** AI 운영·표준화·다브랜드·풀필먼트로 남들이 못 넘는 장벽을 넘을 수 있으면 → **진짜 기회.**
→ 3관문 통과 시에만 브랜드 가설로 승격. **"고객이 왜 다른 브랜드가 아니라 우리를 선택하는가"를 한 문장(USP)으로** 못 쓰면 아직 가설이 아니다.

## 3. [창조] 브랜드 설계 — 하나의 정답이 아니라 여러 버전
- **컨셉·페르소나·USP·네이밍·메뉴 라인업(메인/사이드/세트)·가격·비주얼**을 설계.
- **한 방에 정답 X → 3~5버전을 빠르게** 만들어 비교·베팅. (JD: "여러 아이디어를 빠르게 만들어 비교")
- **내 무기:**
  - **부동산 USP 훈련** — 입지 데이터를 결정 언어로 번역해 '시세보다 4~6억↓' USP를 세워본 것처럼, 카테고리 데이터를 "고객이 살 이유 한 줄"로 번역.
  - **생성형 AI 제작** — 네이밍·메뉴판 카피·대표 이미지 시안을 생성형 AI로 10버전 빠르게(콘텐츠+AI 빌드 경험). "AI에게 시켜 빠르게 뽑는다"를 남보다 능숙하게.
  - **콘텐츠 후킹 감각** — 대표 이미지·메뉴명은 배달앱의 '첫 3초'. 주목을 만드는 순서를 설계.

## 4. [적용·검증] 런칭 & 신호 vs 노이즈 (Framework B)
- 실제 오픈 → 며칠 만에 진짜 고객 반응으로 검증(블리츠의 흔치 않은 강점).
- **신호 vs 노이즈 판별(가장 중요한 안목):**
  - **표본 경계:** 소량 주문의 별점 5.0은 노이즈. 의미 있는 주문 수 확보 후 판단.
  - **신호 우선순위:** 할인 제외 **재구매율** > 리뷰 텍스트의 **반복 패턴** > **CVR** > 단순 주문 수·별점.
  - **노이즈 경계:** 오픈 이벤트·할인빨 주문(할인 빼면 남나?), 지인 리뷰, 단발 바이럴.
  - **핵심 질문:** *"할인 없이도 재구매가 붙는가."* → 초기엔 **재구매 코호트**를 본다.
- 신호가 확인되면 메뉴·가격·컨셉을 **한 번에 하나씩** 바꿔(변수 통제) 재검증.

## 5. [1등·공식화] 반복해서 이기고, 공식으로 남긴다
- 관찰→가설→적용→검증 사이클을 돌려 카테고리 1등까지.
- **성공·실패를 문서로 공식화** — 어떤 신호가 승리로 이어졌는지, 어떤 빈자리가 지뢰였는지를 **재사용 가능한 플레이북**으로. (JD: "우리만의 공식으로 남긴다" + 내 강점: MS AI School 문서화·히스토리 공유)
- 운영을 Agent가 맡으니, 검증된 공식으로 **여러 카테고리를 동시에** 굴리는 데까지 확장.

## 30 · 60 · 90일
- **~30일:** 맡은 카테고리 전수 스캔 → 리뷰 LLM 분석 → **카테고리 지도 + 빈 영역 후보 3개**(Framework A 통과분).
- **~60일:** 최우선 빈 영역으로 **브랜드 가설 + 3~5버전 설계**(컨셉·USP·메뉴·가격·네이밍·비주얼) → 베팅안 확정.
- **~90일:** 런칭·초기 데이터 검증(Framework B) → 1차 수정 사이클 → **성공/실패 공식 문서화** 착수.

## 워크드 예시 (1인 국밥/해장국)
- 빈 영역 가설: "1인 저가 진입 + 결제금액 대비 든든함" 부재.
- Framework A: 수요신호(배민 한그릇 주문 123%↑) ○ / 공급 없는 이유(1인분 객단가 낮음)는 **세트·옵션으로 객단가 보전**해 우회 가능 ○ / 블리츠 운영표준화로 재현성 ○ → 베팅.
- 설계: 9,900원 진입 + 12,900원 든든세트, USP "혼자 먹어도 부담 없는 든든한 한 끼", 썸네일=건더기·포만감.
- 검증: 할인 제외 14일 재구매율 + "양"·"가성비" 리뷰 키워드 추적. (상세: `블리츠-마켓인텔리전스-국밥카드.md`)
