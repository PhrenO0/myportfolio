# 블리츠 입사 후 전략 v2 — 브랜드 메이커 × 그로스 플레이북 (암묵지 풀이 포함)

> 직무 실체(상세 JD): **브랜드 메이커** — 배달 100개 카테고리 중 하나를 맡아, 빈 영역을 찾아 **컨셉·네이밍·메뉴·가격·비주얼까지 브랜드를 직접 설계·런칭하고, 초기 데이터로 고쳐 카테고리 1등**으로 만든다. 운영은 Agent(AKOS/공고상)가 대신.
> 이 문서 = 내가 제안하는 "우리만의 공식" 초안. 어려운 용어는 〔쉽게〕로 풀었다.

---

## 0. 직무의 본질 (뾰족하게)
**브랜드 메이커 = 카테고리 하나를 맡은 미니 PO(프로덕트 오너).**
- **프로덕트 일**(=핵심 가치 창조): 어떤 브랜드·메뉴를 만들지 정의.
- **그로스 일**(=그 가치가 최대한 팔리게): 데이터·실험으로 1등까지 성장.
- 운영을 Agent가 대신하므로 나는 **'무엇을 만들지 + 어디에 베팅할지'** 판단·창조에 집중. → 그래서 이 자리가 **PO/창업가 훈련**이다.

---

## 1. 그로스의 원리 (암묵지 풀이 — 이 일의 '운영체제')
> 브랜드 메이커의 일은 결국 그로스다. 그로스의 원리를 모르면 감으로 일하게 된다.

**(1) 그로스란?** 〔쉽게〕 **핵심 지표 하나를 정하고, 실험으로 배우며, 빠르게 반복해 성장시키는 것.** '성장'의 정체는 회사 단계마다 다르다(It depends) — 초기엔 매출보다 '팔리는 브랜드'를 만드는 게 먼저일 수 있다.

**(2) ★ Output vs Input — 이 전략의 심장** 〔쉽게: 농구 비유〕
- 농구에서 "점수 더 내!" 외치며 슛만 난사하면 진다. **점수(Output)** 는 패스·스크린·매치업 같은 **플레이(Input)** 가 쌓인 결과다.
- **블리츠 적용:** "카테고리 1등 해!"(Output)는 **직접 못 만든다.** 1등은 **재구매·전환·객단가·리뷰(Input)** 가 쌓인 결과다. → 나는 1등을 외치는 대신 **Input을 건드린다.**
- 〔암묵지〕 초보는 Output("매출")을 직접 잡으려 하고, 고수는 Output을 Input으로 쪼갠 뒤 Input을 공략한다.

**(3) 레버(Lever, 지렛대)** 〔쉽게〕 하나의 Input을 움직이는 방법은 여러 개다. 이 각각이 '레버'.
- ⚠️ **대증요법 경계(가장 흔한 실수):** "매출 떨어졌으니 할인 이벤트"는 열나니까 해열제 먹는 격 — 증상만 누른다. **머리에 먼저 떠오르는 레버부터 당기지 말고**, 어떤 Input이 약한지 진단한 뒤 **여러 레버 중 우선순위**를 정해 당긴다.

**(4) 실험(Experiment)** 〔쉽게〕 **가설과 성공 기준을 미리 정하고, 일부만 테스트해 확인하는 것.**
- 왜 하나? ① 유저는 내 예상대로 안 움직인다 ② 전체에 바로 적용하면 리스크가 크다(일부만 → 손해 최소화).
- 〔암묵지〕 **실험 10번 중 8~9번은 실패가 정상.** 그래서 **얼마나 빨리 반복하느냐가 성패.** 블리츠는 실제 매장을 열어 며칠 만에 검증하니 이 속도가 무기.

**(5) 프로덕트 vs 그로스** 〔쉽게〕 프로덕트 = **핵심 가치를 만드는 것**, 그로스 = **그 가치를 최대한 많은 사람이 경험하게 하는 것.** 브랜드 메이커는 **둘 다** 한다(브랜드를 만들고 + 팔리게 키운다). → 이게 PO/창업가로 가는 이유.

**(6) ★ 병목 찾기 (Bottleneck)** 〔쉽게〕 성장이 막히는 진짜 지점. "더 알리자" 전에 **"어디서 막히는가"**부터.
- 〔암묵지〕 성장은 늘 유입 부족 때문에 막히는 게 아니다. **활성화가 낮은데 광고비를 쓰는 건 깨진 양동이에 물 붓기**, 리텐션 낮은데 쿠폰 뿌리기는 잠깐 매출만 올리고 남을 이유는 못 만든다.
- 배달 번역: "주문이 안 는다" → 노출이 없나(유입) / 들어와서 안 사나(전환) / 한 번 먹고 안 오나(유지) / 리뷰가 안 쌓이나(추천) / 팔아도 안 남나(수익) — **단계마다 처방이 다르다.**

**(7) AARRR 퍼널** 〔쉽게〕 고객 여정을 5단계로: **유입(Acquisition)–활성화(Activation)–유지(Retention)–추천(Referral)–수익(Revenue).** "마케팅이 안 된다"는 막연함을 다섯 칸으로 쪼개는 틀.
- 〔암묵지〕 유입은 "많이 왔다"보다 **"좋은 고객이 왔다"**(할인 헌터 vs 재주문할 단골). 활성화는 가입이 아니라 **첫 가치 체감**("이 집 괜찮네"의 순간). 리텐션은 **성장의 체력**(새 물만 계속 붓는 구조 경계). 추천은 억지 장치보다 **말하고 싶어지는 경험**이 먼저.

**(8) 허무 지표 (Vanity Metrics)** 〔쉽게〕 커 보이지만 의사결정에 도움 안 되는 숫자(조회수·팔로워·단순 주문 수).
- 〔암묵지〕 구독자 10만에 오픈율 5%보다, 구독자 5천에 오픈율 45%가 건강한 자산. **그로스는 숫자를 많이 보는 게 아니라 숫자 사이의 관계를 보는 일** — 활성화↑→리텐션↑→LTV↑→감당 가능한 CAC↑, 추천↑→CAC↓.

**(9) 가설 문장 템플릿** 〔쉽게〕 **"우리는 [고객]이 [문제] 때문에 [행동]을 하지 않는다고 믿는다. 따라서 [변경]하면 [지표]가 개선될 것이다."**
- 배달 예시: "봉천 1인 가구가 최소주문금액·배달비 부담 때문에 첫 주문을 망설인다고 믿는다 → 9,900원 1인 세트를 무료배달로 노출하면 신규 주문 전환율이 오를 것이다."
- 〔암묵지〕 이렇게 써두면 **실패해도 어떤 믿음이 틀렸는지 배운다** → 잘 기록된 실패 = 자산. 가설 없이 이것저것 바꾸면 결과가 나와도 배움이 없다.

**(10) AI 시대의 실험 원칙** 〔쉽게〕 AI가 실험 비용을 낮출수록 **우선순위가 더 중요**해진다.
- **AI에게: 초안·변형·요약·분류·반복 / 사람에게: 고객 판단·브랜드 방향·실험 우선순위·윤리·최종 결정.**
- 한꺼번에 다 바꾸면 무엇이 효과였는지 몰라 배움을 잃는다(변수 통제). "AI는 그로스를 대신해주지 않는다. 좋은 질문을 던지는 팀에게 더 빠른 학습 능력을 줄 뿐."

## 2. 블리츠 지표 트리 (내가 세울 프레임워크: Output → Input → 레버)
> "1등"이라는 Output을, 매일 관리할 수 있는 Input과 레버로 분해한다. 이 트리가 곧 나의 판단 지도.

**North Star(Output):** 카테고리 1등 = **"할인 없이도 재구매가 붙는, 남는 브랜드."** (단순 주문 수 아님)

| Input(선행지표) | 〔쉽게〕 | 당길 수 있는 레버 |
|---|---|---|
| 노출·**CTR** | 목록에서 눌리는 비율 | 대표 이미지·메뉴명·별점·인기 라벨·배달비 표시 |
| 전환·**CVR** | 들어와서 실제 사는 비율 | 상세 구성·가격·첫 리뷰·세트 제안 |
| **객단가** | 주문당 결제액 | 세트·옵션(고기추가)·번들 |
| **재구매율(14/30일)** ★ | 다시 시키는 비율 = 1등의 핵심 | 맛·양·포장 일관성·리텐션 쿠폰 |
| 리뷰 **긍정률** | 신뢰·노출을 만드는 신호 | 초기 리뷰 시딩·사진리뷰 유도·불만 즉시 개선 |
| **공헌이익** | 한 그릇 팔면 남는 돈 | 원가·수수료·할인 설계 |

**AARRR 매핑:** 노출·CTR=유입 / 첫 주문·만족한 첫 끼=활성화 / 재구매율=유지 / 리뷰·찜=추천 / 객단가·공헌이익=수익. → 위 Input 표는 곧 **배달판 AARRR.**

**레버 우선순위 정하는 법:** ① 지금 가장 약한 Input(=병목)을 찾고(진단) ② 그 Input을 가장 크게·빠르게 움직일 레버부터. (전부 다 하지 않는다 — 허무 지표에 홀리지 않는다.)

## 3. 브랜드 메이킹 사이클 (Discovery → Delivery)
> 그로스 PM의 일은 Discovery(무엇을 만들/실험할지 정의) + Delivery(실제로 굴려 검증)로 나뉜다. 브랜드 메이커도 똑같다.

### Discovery — 무엇을 만들지 정의
1. **카테고리 진단(관찰):** 상위 브랜드 전수 스캔 + 리뷰 수천 개를 LLM으로 태깅·클러스터링 → 강점 패턴·공백 지도화.
2. **빈 영역 검증(가설):** 아래 §4-A 3관문 통과분만 승격. **USP 한 문장** 못 쓰면 아직 가설 아님.
3. **지표 트리·성공 기준 사전 정의:** 이 브랜드의 North Star와 핵심 Input, 그리고 "무엇이 나오면 성공/실패"를 **런칭 전에** 못 박는다. (사후 정당화 방지)

### Delivery — 실제로 굴려 검증
4. **여러 버전 제작:** 컨셉·USP·네이밍·메뉴·가격·비주얼을 3~5버전 빠르게(생성형 AI 활용) → 베팅.
5. **런칭 실험:** 실제 오픈해 며칠 만에 진짜 반응 확인.
6. **신호 vs 노이즈 판별(§4-B)** → 유효 신호만 채택.
7. **레버 하나씩 수정(변수 통제):** 한 번에 하나만 바꿔 무엇이 효과였는지 규명.
8. **회고·공식화:** 승리/실패 패턴을 재사용 가능한 플레이북으로 남긴다(JD의 "우리만의 공식").

## 4. 두 판별 프레임워크 (브랜드 메이커의 안목)

### 4-A. 빈 영역 = 기회 vs 지뢰 (3관문)
1. **수요 신호 있나?** 급상승 키워드·검색량, 리뷰의 "이런 거 없나요" 요청. (없으면 그냥 니치)
2. **공급이 없는 '이유'가 치명적인가?** 원가율·조리 난이도·배달 부적합(눅눅·국물)·낮은 객단가. (구조적이면 지뢰)
3. **그 이유를 '블리츠라서' 우회 가능한가?** AI 운영·표준화·다브랜드·세트 설계로 넘으면 → **진짜 기회.**

### 4-B. 신호 vs 노이즈 (초기 데이터 판별)
- **표본 경계:** 소량 주문의 별점 5.0 = 노이즈. 의미 있는 주문 수 확보 후 판단.
- **신호 우선순위:** 할인 제외 **재구매율** > 리뷰 텍스트 **반복 패턴** > **CVR** > 단순 주문 수·별점.
- **노이즈 경계:** 오픈 이벤트·할인빨 주문(할인 빼면 남나?), 지인 리뷰, 단발 바이럴.
- **핵심 질문:** *"할인 없이도 재구매가 붙는가."* → 초기엔 **재구매 코호트**를 본다.

## 5. 왜 내가 남보다 잘하나 (Unfair Advantage)
| 브랜드 메이커에 필요한 것 | 내 근거 |
|---|---|
| 데이터로 미충족 수요 규명 | 질적연구(유학생 7명·38문항·삼각검증) + 리뷰 LLM 클러스터링 |
| "살 이유(USP)" 한 줄 번역 | 부동산 '시세보다 4~6억↓' USP·사업타당성 발표 |
| Output→Input→레버로 사고 | 콘텐츠 A/B(잘된/안된 비교로 원인 규명), AdGuard 근거 기반 검증 |
| AI로 데이터·에셋 빠르게 생성 | neural-flow·MS AI School LLM/멀티에이전트 직접 설계·배포 |
| 첫 3초 주목(이미지·네이밍) | 영상 후킹, 남양주 숏폼 최고 10만·구리시 우수상 |
| 실험 회고·공식화 | MS AI School 마일스톤·문서·히스토리 공유로 팀 정렬 |

## 6. 30 · 60 · 90일
- **~30일:** 카테고리 전수 스캔 + 리뷰 LLM 분석 → **카테고리 지도 + 지표 트리 + 빈 영역 후보 3개**(3관문 통과분).
- **~60일:** 최우선 빈 영역 → **브랜드 가설 + 3~5버전 설계** + 성공 기준 사전 정의 → 베팅안 확정.
- **~90일:** 런칭·검증(신호 vs 노이즈) → 레버 1개씩 수정 사이클 → **성공/실패 공식 문서화** 착수.

## 부록. 워크드 예시 — 1인 국밥/해장국 (Output→Input→레버)
- **Output:** 1인 국밥 카테고리 1등(할인 제외 재구매 기준).
- **약한 Input 가설:** CVR·재구매율 (진입가·양 불만).
- **레버 선택:** 진입가 9,900원 + 12,900 든든세트(객단가), 썸네일=건더기·포만감(CTR), '양 많음' 리뷰 시딩(긍정률), 고기추가 옵션(양 불만→객단가).
- **USP:** "혼자 먹어도 부담 없는 든든한 한 끼."
- **성공 기준(사전):** 2주 후 할인 제외 14일 재구매율 X% 이상 + '양/가성비' 긍정 리뷰 비중 Y% 이상.
- **3관문:** 수요신호(배민 한그릇 123%↑)○ / 낮은 객단가는 세트로 우회○ / 블리츠 표준화로 재현성○ → 베팅. (상세: `블리츠-마켓인텔리전스-국밥카드.md`)

> ⚠️ 정직성: 지표 트리·전략은 공고+시장 데이터 기반 내 제안. AKOS/매출 목표 등은 회사 제시. 실제 데이터 접근·우선순위는 입사 후 팀과 조정.
