# ⑤ 커리어 축 · 그로스/PO 직무 지침 (2026 추가)

> 상세: `커리어-정체성.md` · `블리츠-입사후전략.md` · `블리츠-회사분석.md`. 그로스형/기획/PO 직무 지원 시 이 축으로 통일.

## 커리어 정체성 (한 줄)
**기술을 직접 만들 줄 알고, 데이터로 시장을 읽어 파는 — 빌더형 프로덕트 오너(PO) 지향.**
- **마케팅·그로스는 정체성이 아니라 PO로 가기 위해 쌓는 역량.** ("기술 아는 마케터가 되겠다" ❌ → "기술·그로스를 아는 프로덕트 오너가 되겠다" ✅)
- **사다리:** (지금) 그로스형 F&B MD/브랜드 메이커 → 그로스 PM/PMM → **PO** → CPO/창업가.
- **롤모델:** 김슬아(컬리)·김봉진(배민)·케빈 시스트롬(인스타) — 비개발/크리에이티브 출신이 제품·시장 감각으로 프로덕트 리더·창업가가 된 사례.
- ※ 마스터 정체성 "소비자·콘텐츠 AI 프로덕트 기획자 = 짓고 파는 메이커"의 **사업화 심화**. 모순 아님(둘 다 '짓고 파는 사람'). 특정 직무 지원 시 "그로스 마케터"로 라벨을 좁히되 **정체성은 PO/빌더**로 유지.

## 그로스 원칙 (그로스/기획 직무 답변·전략의 기준)
1. **Output vs Input:** 매출·1등(Output)은 직접 못 만든다 → Input(재구매·전환·객단가·리뷰)으로 쪼개 공략. (농구: 점수는 플레이의 결과)
2. **레버 우선순위:** 여러 지렛대 중 '가장 약한 Input × 큰 효과'부터. **대증요법("떨어졌으니 할인/푸시") 금지.**
3. **실험:** 가설·성공기준 **사전 정의**, 일부만, **10중 8~9 실패 전제** → 반복 속도가 성패. 본질은 트릭이 아니라 **학습 속도** — 잘 기록된 실패는 자산.
4. **선행지표 중심:** 후행지표(매출)보다 선행지표(재구매·활성)를 관리.
5. **프로덕트=가치 창조 / 그로스=가치 확산.** 브랜드 메이커·PO는 둘 다.
6. **병목 우선:** "더 알리자" 전에 "어디서 막히는가"(AARRR: 유입–활성화–유지–추천–수익 중 어느 칸). 활성화 낮은데 광고 = 깨진 양동이.
7. **허무 지표 경계:** 조회수·팔로워·단순 주문 수 말고 여정의 질(활성화율·리텐션·CAC·LTV). 지표는 개수가 아니라 **관계**로 본다.
8. **가설 템플릿:** "[고객]이 [문제] 때문에 [행동]을 안 한다고 믿는다 → [변경]하면 [지표]가 개선될 것이다." 가설 없이 바꾸면 배움이 없다.
9. **AI 경계:** AI=초안·변형·요약·분류·반복 / 사람=고객 판단·방향·우선순위·윤리·최종 결정. 실험 비용이 낮아질수록 우선순위가 중요.

## 지원동기 축 (블리츠 등 그로스/브랜드 직무)
PO가 되려면 **①기술 아는 눈 + ②시장 읽는 눈**이 필요 → 나는 ①AI 직접 빌드(neural-flow·MS AI School), ②부동산·질적연구·콘텐츠로 갖춤 → **부족한 조각 = "데이터로 무엇이 팔리는지 규명해 상품으로 옮기는 근육"** → 그 조각을 채우는 자리가 이 인턴. **"이 인턴은 내 커리어 맵의 첫 실전."**
- ⚠️ 안전장치: PO·창업가는 **먼 방향으로만 겸손하게.** 현 직무를 임시취급하는 뉘앙스 금지(딴 직무 원하는 걸로 보임).

## 직무 이해 (블리츠 브랜드 메이커)
**카테고리 PO = 프로덕트(브랜드 설계) + 그로스(1등까지 실험).** 광고 집행 아님. **관찰-가설-적용-검증** 사이클을 돌려 카테고리 1등 + 공식화. 지표는 Output(1등)→Input(재구매·CVR·객단가·리뷰)→레버로 분해해 관리.

# 자기소개서 전략 (마스터 지침)

> 출처: Notion `자기소개서 전략`. 자소서는 글쓰기 과제가 아니라 **나라는 사람을 채용자 관점에서 해석시키는 기획서**다.
> 핵심: **좋은 자소서는 '멋진 문장'이 아니라, 내가 어떤 문제를 어떤 방식으로 해결해온 사람인지 납득시키는 글이다.**

## 1. 쓰기 전에 먼저 정할 것 (5가지)

1. 지원 직무
2. 지원 산업/회사
3. 보여주고 싶은 핵심 역량
4. 그 역량을 증명할 경험
5. 회사가 나를 뽑아야 하는 이유

경험이 여러 방향(미디어·도시계획·AI·영상·Azure·창업)으로 흩어져 있으므로, **중심 문장은 하나여야** 한다.

> 예) **저는 사용자 경험과 데이터, AI 기술을 연결해 실제 문제를 제품 구조로 바꾸는 서비스기획자입니다.**

이 중심 문장을 먼저 잡고 모든 경험을 거기에 맞게 재배열한다.

## 2. 평가 기준 (검증용 — 칭찬 말고 비판하게)

1. 직무 적합성이 명확한가
2. 경험이 구체적인가
3. 내가 한 행동이 보이는가
4. 성과나 배운 점이 있는가
5. 문장이 추상적이거나 GPT스럽지 않은가
6. 뽑고 싶은 사람처럼 보이는가

## 3. 기본 문단 구조

```
1. 주장      → 저는 ~한 사람입니다.
2. 근거 경험  → 이 역량은 ~경험에서 구체화되었습니다.
3. 내 행동    → 당시 문제는 ~였고, 저는 ~를 했습니다.
4. 결과·배움  → 그 결과 ~를 얻었습니다.
5. 직무 연결  → 이 경험으로 ~직무에서 ~에 기여하고 싶습니다.
```

중요한 건 **문장력보다 논리의 흐름.**

## 4. 작성 규칙

- **규칙 1.** "관심이 있습니다"만 쓰지 말기 → 경험으로 생긴 **관점**을 써라.
- **규칙 2.** "많이 배웠습니다" 금지 → 배운 점은 **구체적으로.**
- **규칙 3.** "다양한 경험을 했습니다" 금지 → 다양한 경험을 **하나의 방향**으로 묶어라.
- **규칙 4.** 프로젝트 이름만 나열 금지 → **내가 어떤 문제를 어떻게 구조화했는지**가 핵심.
- **규칙 5.** 성과 수치가 없으면 **구조(문제정의·판단·설계·역할·개선)로** 보여줘라.

## 5. 문항별 구조 전략

- **지원동기**: 회사/직무가 다루는 문제 → 관심 계기 → 내 경험 연결 → 기여 방향. (회사 칭찬으로 시작 금지. **내 문제의식과 회사의 일이 만나는 지점**에서 시작.)
- **직무역량**: 역량 정의 → 발휘 경험 → 구체 행동 → 결과/배움 → 직무 적용.
- **협업경험**: 팀 상황 → 갈등/문제 → 내가 한 조율 → 결과 → 협업관. ("소통했습니다" 아니라 **서로 다른 역할을 어떻게 맞췄는지**.)
- **창의성/도전**: 기존 방식의 한계 → 새 접근 → 실행 → 어려움 → 결과. (A.INUS·AdGuard 추천)
- **입사 후 포부**: 방향성 → 초기에 할 일 → 중장기 가치. (거창하면 안 됨. 초기 3개월 행동 구체화.)

## 6. 작성 순서 (절대 완성본부터 쓰지 말 것)

```
1. 지원 직무 정하기
2. 채용공고 분석
3. 경험 재료표 만들기
4. 문항별 경험 매칭
5. 각 문항 핵심 주장 1문장
6. STAR 구조 정리
7. 초안 작성
8. 채용자 관점 비판 받기
9. 자연스럽게 재작성
10. 최종 사실 검수
```

> **정리 → 매칭 → 초안 → 비판 → 재작성.**

## 7. 절대 하면 안 되는 것

- 채용공고 없이 쓰기 / 경험 뭉뚱그리기 / 과장된 성과 / 너무 매끈한 문장 / 회사마다 같은 글 / AI 추상어 그대로 / 사실 확인 없이 기술명. → 상세: `지침.md` ③ 정직성

## 8. 포지셔닝 (직무별)

- **기본값**: AI와 콘텐츠, 공간/시장 맥락을 연결해 실제 사용자가 이해하고 행동할 수 있는 서비스 경험으로 바꾸는 기획자.
- **AI 서비스기획**: AI 기능을 사용자 문제와 서비스 흐름 안에 배치하는 기획자.
- **콘텐츠/브랜드 기획**: AI와 스토리텔링으로 브랜드 경험을 구체적 장면·메시지로 만드는 기획자.
- **프롭테크/공간**: 공간·시장 데이터를 사용자 의사결정에 연결하는 AI 서비스기획자.
- **창업/스타트업**: 현실 문제를 빠르게 구조화하고 AI로 MVP 검증하는 Product Builder.

## 9. 최종 규칙

```
1. 경험보다 관점이 중요하다.
2. 관점보다 근거가 중요하다.
3. 근거보다 직무 연결이 중요하다.
4. 문장은 화려하지 않아도 된다.
5. 내가 한 행동이 보여야 한다.
6. 회사가 뽑을 이유가 있어야 한다.
7. GPT는 초안 도구가 아니라 사고를 정리하는 도구다.
```

> **자소서를 맡기지 말고, 내 경험을 직무 언어로 번역하게 만들어라.**

```

- 자소서 문항: []

[기업 정보 참고] (홈페이지/채용공고/최근 뉴스/사업 방향 붙여넣기)
→ [여기에 기업 정보 붙여넣기]

[내 기존 자소서]
→ [여기에 기존 자소서 붙여넣기]

[커스텀 조건 — 반드시 지킬 것]

2. 이 기업만의 언어로 바꿔. 인재상·핵심가치·최근 사업 방향을 반드시 녹여라. 경쟁사에도 쓸 수 있는 문장이면 다시 써.
3. 뻔한 표현 전면 금지. '귀사' '지원하게 되었습니다' '성장하고 싶습니다' 쓰면 다시 써.
4. 첫 문장은 이 기업 면접관이 읽다가 멈추게 만드는 문장으로. '저는'으로 시작 절대 금지.
5. 커스텀 완료 후 아래도 알려줘:
   1) 기존 자소서 대비 달라진 점 3가지
   2) 이 기업 면접에서 나올 수 있는 예상 질문 3개
   3) 이 기업에 더 어필하려면 추가하면 좋을 경험이나 키워드
```

# 정직성 규칙 (날조 0) — 절대 규칙

> 모든 자소서 생성·변주에서 **반드시** 지켜야 하는 사실 경계. 어기면 날조.
> 마스터본은 7차례 검증으로 날조 0을 통과함. 새 출력도 이 표를 기준으로 검수할 것.

## ⛔ 절대 규칙

| 항목 | 사실 경계 (이것만 사실) | 하면 안 되는 것 (날조) |
|---|---|---|
| **무신사 AI 광고 공모전** | 참가·멀티에이전트 설계 경험만 서술 | **수상 표기 0** — "수상/입상" 절대 금지 |
| **A.INUS (Masterpiece Needs Wings)** | **팀 수상** (콘텐츠 공모전) | 개인 단독 수상으로 쓰지 말 것 |
| **E-Nudge** | 공감형 넛지 **설계·기획까지만** | 모델 단독 개발/운영 성과로 부풀리지 말 것 |

# ④ 스토리텔링 설계 & 검증 루프

> 상세 블루프린트는 `스토리텔링-설계도.md` (3각 리서치 종합: 글로벌 커버레터·한국 합격자소서·서사구조 이론). 여기엔 운영 핵심만.

## 4-A. 거시 서사 (4문항 = 한 사람의 여정)

- **through-line 1문장 먼저** 정하고, 안 맞는 소재는 잘라냄(멀티테마 드리프트 = 최대 실패).
- **단일 모티프 1개를 문항당 1회 의도된 콜백**(흩뿌리면 AI티, 1회면 설계). 마지막 문항에서 **자신에게 반전**.
- 매크로 아크 = 영웅서사: **②③④ 주인공 변화 → ① StoryBrand 가이드**(회사·유저가 주인공, 나=안내자). 점증하는 단일 스테이크(한 멘티→시청자 다수→나→회사 유저).
- 문항별: ① StoryBrand+Duarte 대비리듬 / ②③ Pixar Story Spine(인과 '그래서') / ④ 강점→그림자→교정 미니아크.
- 장면 오프닝(in medias res)+호기심 갭(Zeigarnik), 갈등→수치 결과(Show-don't-tell), 현재진행 마무리('~하고자 합니다').

## 4-B. 'AI티' 제거 (im-not-ai / humanize-korean)

- 패턴: **C-11**(연결어미 뒤 쉼표), **D-7**('X를 Y로' 변환공식), **E**(리듬 균일·종결어미 반복·명사종결 경구), 동일수사 반복, 헤징.
- ★4대 철칙: 의미·수치 **100% 보존** · 탐지 span만 수정 · 장르 유지 · 변경률 **30% 초과 경고**.
- 금지: '저는 ~한 인재입니다'·'어릴 적부터'·'노력하겠습니다/감사합니다'·진부어(성실·노력·책임감·창의적)·부정어 선두.

## 4-C. 적대적 검증 루프 (★윤문 후 필수)

- **5렌즈 병렬 감사**(정직성·AI티·방법론·보이스·경쟁력) → 종합 판정 → 수정 → **재검증**.
