# 자기소개서 전략 (마스터 지침)

> 출처: Notion `자기소개서 전략`. 자소서는 글쓰기 과제가 아니라 **나라는 사람을 채용자 관점에서 해석시키는 기획서**다.
> 핵심: **좋은 자소서는 '멋진 문장'이 아니라, 내가 어떤 문제를 어떤 방식으로 해결해온 사람인지 납득시키는 글이다.**

## 1. 쓰기 전에 먼저 정할 것 (5가지)

1. 지원 직무
2. 지원 산업/회사
3. 보여주고 싶은 핵심 역량
4. 그 역량을 증명할 경험
5. 회사가 나를 뽑아야 하는 이유

경험이 여러 방향(미디어·도시계획·AI·영상·Azure·창업)으로 흩어져 있으므로, **중심 문장은 하나여야** 한다.

> 예) **저는 사용자 경험과 데이터, AI 기술을 연결해 실제 문제를 제품 구조로 바꾸는 서비스기획자입니다.**

이 중심 문장을 먼저 잡고 모든 경험을 거기에 맞게 재배열한다.

## 2. 평가 기준 (검증용 — 칭찬 말고 비판하게)

1. 직무 적합성이 명확한가
2. 경험이 구체적인가
3. 내가 한 행동이 보이는가
4. 성과나 배운 점이 있는가
5. 문장이 추상적이거나 GPT스럽지 않은가
6. 뽑고 싶은 사람처럼 보이는가

## 3. 기본 문단 구조

```
1. 주장      → 저는 ~한 사람입니다.
2. 근거 경험  → 이 역량은 ~경험에서 구체화되었습니다.
3. 내 행동    → 당시 문제는 ~였고, 저는 ~를 했습니다.
4. 결과·배움  → 그 결과 ~를 얻었습니다.
5. 직무 연결  → 이 경험으로 ~직무에서 ~에 기여하고 싶습니다.
```

중요한 건 **문장력보다 논리의 흐름.**

## 4. 작성 규칙

- **규칙 1.** "관심이 있습니다"만 쓰지 말기 → 경험으로 생긴 **관점**을 써라.
- **규칙 2.** "많이 배웠습니다" 금지 → 배운 점은 **구체적으로.**
- **규칙 3.** "다양한 경험을 했습니다" 금지 → 다양한 경험을 **하나의 방향**으로 묶어라.
- **규칙 4.** 프로젝트 이름만 나열 금지 → **내가 어떤 문제를 어떻게 구조화했는지**가 핵심.
- **규칙 5.** 성과 수치가 없으면 **구조(문제정의·판단·설계·역할·개선)로** 보여줘라.

## 5. 문항별 구조 전략

- **지원동기**: 회사/직무가 다루는 문제 → 관심 계기 → 내 경험 연결 → 기여 방향. (회사 칭찬으로 시작 금지. **내 문제의식과 회사의 일이 만나는 지점**에서 시작.)
- **직무역량**: 역량 정의 → 발휘 경험 → 구체 행동 → 결과/배움 → 직무 적용.
- **협업경험**: 팀 상황 → 갈등/문제 → 내가 한 조율 → 결과 → 협업관. ("소통했습니다" 아니라 **서로 다른 역할을 어떻게 맞췄는지**.)
- **창의성/도전**: 기존 방식의 한계 → 새 접근 → 실행 → 어려움 → 결과. (A.INUS·AdGuard 추천)
- **입사 후 포부**: 방향성 → 초기에 할 일 → 중장기 가치. (거창하면 안 됨. 초기 3개월 행동 구체화.)

## 6. 작성 순서 (절대 완성본부터 쓰지 말 것)

```
1. 지원 직무 정하기
2. 채용공고 분석
3. 경험 재료표 만들기
4. 문항별 경험 매칭
5. 각 문항 핵심 주장 1문장
6. STAR 구조 정리
7. 초안 작성
8. 채용자 관점 비판 받기
9. 자연스럽게 재작성
10. 최종 사실 검수
```

> **정리 → 매칭 → 초안 → 비판 → 재작성.**

## 7. 절대 하면 안 되는 것

- 채용공고 없이 쓰기 / 경험 뭉뚱그리기 / 과장된 성과 / 너무 매끈한 문장 / 회사마다 같은 글 / AI 추상어 그대로 / 사실 확인 없이 기술명. → 상세: `지침.md` ③ 정직성

## 8. 포지셔닝 (직무별)

- **기본값**: AI와 콘텐츠, 공간/시장 맥락을 연결해 실제 사용자가 이해하고 행동할 수 있는 서비스 경험으로 바꾸는 기획자.
- **AI 서비스기획**: AI 기능을 사용자 문제와 서비스 흐름 안에 배치하는 기획자.
- **콘텐츠/브랜드 기획**: AI와 스토리텔링으로 브랜드 경험을 구체적 장면·메시지로 만드는 기획자.
- **프롭테크/공간**: 공간·시장 데이터를 사용자 의사결정에 연결하는 AI 서비스기획자.
- **창업/스타트업**: 현실 문제를 빠르게 구조화하고 AI로 MVP 검증하는 Product Builder.

## 9. 최종 규칙

```
1. 경험보다 관점이 중요하다.
2. 관점보다 근거가 중요하다.
3. 근거보다 직무 연결이 중요하다.
4. 문장은 화려하지 않아도 된다.
5. 내가 한 행동이 보여야 한다.
6. 회사가 뽑을 이유가 있어야 한다.
7. GPT는 초안 도구가 아니라 사고를 정리하는 도구다.
```

> **자소서를 맡기지 말고, 내 경험을 직무 언어로 번역하게 만들어라.**

```

- 기업명: []
- 지원 직무: []
- 자소서 문항: []

[기업 정보 참고] (홈페이지/채용공고/최근 뉴스/사업 방향 붙여넣기)
→ [여기에 기업 정보 붙여넣기]

[내 기존 자소서]
→ [여기에 기존 자소서 붙여넣기]

[커스텀 조건 — 반드시 지킬 것]

2. 이 기업만의 언어로 바꿔. 인재상·핵심가치·최근 사업 방향을 반드시 녹여라. 경쟁사에도 쓸 수 있는 문장이면 다시 써.
3. 뻔한 표현 전면 금지. '귀사' '지원하게 되었습니다' '성장하고 싶습니다' 쓰면 다시 써.
4. 첫 문장은 이 기업 면접관이 읽다가 멈추게 만드는 문장으로. '저는'으로 시작 절대 금지.
5. 커스텀 완료 후 아래도 알려줘:
   1) 기존 자소서 대비 달라진 점 3가지
   2) 이 기업 면접에서 나올 수 있는 예상 질문 3개
   3) 이 기업에 더 어필하려면 추가하면 좋을 경험이나 키워드
```

## neural-flow 연동 메모

- **포지셔닝 기본값**: 소비자·콘텐츠 AI 프로덕트 기획자 (AI로 직접 만드는 콘텐츠·서비스 기획자) — '그로스 마케터'로 좁히지 말 것. (정체성: `../자소서-근본목적.md`)
- **경험 재료**: 경험 자산 DB (E-Nudge·AdGuard·A.INUS·기억의궁전·부동산·선거캠프·시퓨즈·멘토링) → `경험자산.md`
- **문항별 소재**: 지원동기→우리함께/AdGuard · 직무역량→AdGuard/기억의궁전 · 협업→시퓨즈/나는샬롬 · 도전→A.INUS/기억의궁전.
- **회사 톤 모르면**: 채용공고·뉴스 먼저 리서치 후 커스텀.

# 정직성 규칙 (날조 0) — 절대 규칙

> 모든 자소서 생성·변주에서 **반드시** 지켜야 하는 사실 경계. 어기면 날조.
> 마스터본은 7차례 검증으로 날조 0을 통과함. 새 출력도 이 표를 기준으로 검수할 것.

## ⛔ 절대 규칙

| 항목 | 사실 경계 (이것만 사실) | 하면 안 되는 것 (날조) |
|---|---|---|
| **무신사 AI 광고 공모전** | 참가·멀티에이전트 설계 경험만 서술 | **수상 표기 0** — "수상/입상" 절대 금지 |
| **A.INUS (Masterpiece Needs Wings)** | **팀 수상** (콘텐츠 공모전) | 개인 단독 수상으로 쓰지 말 것 |
| **E-Nudge** | 공감형 넛지 **설계·기획까지만** | 모델 단독 개발/운영 성과로 부풀리지 말 것 |
| **3차 프로젝트 (기억의 궁전)** | 본인 = **3D 엔진 & 화면(UI/UX)** 담당 | **GraphRAG는 윤재 담당** — 본인 성과로 가져오지 말 것 |
| **인지과학 근거** | **발표로 정리한 수준까지만** 인용 | 본인이 실험·증명한 것처럼 쓰지 말 것 |
| **금지 디테일** | — | **Lynch(케빈 린치) / 85% / 방배치 10법칙** 표현 금지 (근거 불충분) |

## ✅ 사실로 확정된 수치 (그대로 사용, 변경 금지)

- 우리함께 멘토링: 멘티 **7명**, **16주 10회**, 출석률 **97.8%**
- AdGuard: RAG 청크 **1,069개**, **L1~L5 Cascade**(Rule Engine·RAG Retriever·Judge·Rewriter·Re-Judge = 탐지·근거검색·판정·대안생성·재검증), **Cascade 테스트 10건 중 9건** 정확, **L1 Rule Engine 24/25** 통과, **내부 평가 핵심 지표 100%(67건)**, 체감 **30초**, **Azure AI Search**, MS AI School **9기 2차**, 본인 = **팀장**
  - ※ 위 세 수치는 **서로 다른 지표** — "10건 중 9건"(Cascade end-to-end) ≠ "24/25"(L1 Rule Engine) ≠ "67건 100%"(내부 핵심 지표). 섞어서 한 수치로 만들지 말 것.
- E-Nudge: **MS AI School 9기 1차 프로젝트 평가 1위** (obsidian-vault 정리본으로 확인). 단 넛지 **설계·기획까지만**.
- 한국장학재단 **사회리더 멘토링 수료** (2025.4~11, 약 8개월) — '수료'. 수상 아님.
- 기억의 궁전: **Three.js**, **광화문** 지도 **5곳**, 6주 훈련 회상량 **138%↑**(인용 연구), **2014년 노벨상**(장소·격자 세포)
- 나는샬롬: **22씬 2부작**
- 남양주 지방선거 캠프: **2022년**, 약 **15개** 콘텐츠, 최고 조회수 약 **10만**
- 시퓨즈: **시청자미디어재단** 지원, **3박 4일** 단편영화, 전국 고등학생 멘티
- **2025 구리시 숏폼 영상 공모전 '구리에 빠지다'**: 작품 **'구리 청년의 내일'**로 **우수상** (구리시 공고 제2025-1480호, 2025.9.9. — 공고상 수상자명 '오O상' 마스킹, 본인 확인됨)
- **제68기 금융사관학교 국제경제전문가 과정**: **수료** (㈜금융사관학교, 2025.3.31.) — '수료'이지 수상 아님. 부풀리지 말 것

## ⚠️ 대조 / 확인 항목

- ✅ **AdGuard 수치** — 해소됨. "10건 중 9건"·"24/25"·"67건 100%"는 서로 다른 지표(위 참조). 충돌 아님.
- ✅ **E-Nudge 1위** — obsidian-vault 정리본으로 사실 확인. (마스터본엔 미반영 → **마스터에 1위를 넣을지는 junsang 선택**.)
- ⚠️ **유학생 멘토링 인원** — 마스터본 v7 "멘티 일곱 명·16주 10회" ↔ 정리본 "7명 심층면접 + 멘티 5명 10회차"(16주 표현 없음). → 제출본에 쓸 정본 확정 필요 (멘티 7명 vs 5명, '16주' 유지 여부).
- ⚠️ **하우스 매니저** — 객단가 37,000→43,000원(약 16%↑)은 정리본에 '추가 확인 필요'로 표기됨. 기간·장소·산식 확정 전까지 자소서 사용 보류.

## 원칙 (자소서 전략 문서 §8, §12에서)

- 내가 직접 한 것 / 팀이 한 것 / 참고한 것을 **반드시 구분**.
- 과장된 성과 만들지 않기. 사실 확인 없이 기술명 넣지 않기.
- 성과 수치가 없으면 부풀리지 말고 **구조(문제정의·판단·설계·역할)로** 증명.
